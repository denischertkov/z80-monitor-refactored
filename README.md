# Z80 SBC Monitor — модульный рефакторинг

Основа: расширенный монитор Дениса Черткова на базе монитора Grant Searle.
Целевой ассемблер: **sjasmplus 1.24.0**. Комментарии рабочего кода — на английском;
табуляции заменены пробелами, `;` после кода находится в 41-й позиции строки.
Уведомления авторов сохранены. Исторические baseline и тестовый снимок не форматировались.

Это **только монитор**, собираемый с `ORG $0000`. BASIC не включается,
не перезаписывается исходниками проекта и не заменяется заполнителем.
Архив не содержит готовой, проверенной на плате прошивки.

## Статус проверки

Пользователь подтвердил работу на плате и прохождение всех 13 тестов с настоящей
сборкой: исходный монитор — 2312 байт, первый рефакторинг — 2271, унификация — 2269.
После форматирования локально прошли 12 тестов; сборка пропущена, поскольку здесь
нет sjasmplus. Инструкции и данные сверены с версией до форматирования и не изменены.
`bash -n` для обоих скриптов прошёл. `rom_loader.asm` не был предоставлен;
его алгоритм копирования отдельно не проверялся.

Тестовый интерпретатор исполняет выбранные инструкции из обеих версий
исходника. Он не является полноценным эмулятором Z80: SIO/RST, PRINT и GET2
подменены моделями; такты, все биты F, реальные прерывания и диапазоны JR
этим интерпретатором не проверяются. Проверка настоящей сборкой отдельно
проверяет синтаксис, переходы, размер и начальную разметку бинарника.

## Сборка и тесты

Из корня распакованного проекта:

```bash
bash build.sh
python3 -m unittest discover -s tests -v
```

При наличии sjasmplus тесты собирают `baseline/monitor-sjasmplus.asm`, снимок
предыдущего рефакторинга `tests/fixtures/before-unification.asm` и новый монитор.
Они печатают реальные размеры и сверяют экономию унификации с расчётом длин
инструкций из `tests/size_delta.py`.
Сравнение не побайтовое: адреса внутренних процедур после рефакторинга меняются.
Для запуска тестов достаточно стандартной библиотеки Python 3.8+.

Результаты сборки: `build/monitor-sjasmplus.bin`, `.lst`, `.sym`.
Скрипт сборки не обращается к плате. `ASSERT` проверяет границу BASIC,
RST-векторы, вектор SIO и рабочую RAM. Дополнительно скрипт проверяет размер
бинарника: больше нуля и не более 8192 байт. Заполнение до `$4000` запрещено
самой выбранной схемой обновления и в исходнике отсутствует.

`build_info.inc` — текстовый фрагмент SIGNON без завершающего NUL. В `build.sh`
учтена пользовательская генерация даты перед сборкой. Формат даты YYYY-MM-DD
сохраняет длину строки. BUILD_TIME вычисляется, но в текущую строку не входит.

Синтаксис INCLUDE/ASSERT сверялся с
[официальной документацией sjasmplus](https://z00m128.github.io/sjasmplus/documentation.html).

## Модули

| Файл | Ответственность |
| --- | --- |
| `monitor-sjasmplus.asm` | Порядок включений и проверки итоговой компоновки |
| `src/config.inc` | Порты, управляющие значения, константы BASIC/CP/M |
| `src/workspace.inc` | Фиксированные адреса RAM и границы стека |
| `src/vectors.asm` | Reset, RST $08/$10/$18, вектор IM2 по $0060 |
| `src/serial.asm` | SIO A/B, IRQ, кольцевые буферы, низкоуровневая консоль |
| `src/console_io.asm` | Фильтрация и вывод символов командной строки |
| `src/init.asm` | Инициализация и выбор консоли; продолжение прямо в MAIN |
| `src/commands.asm` | Диспетчер, GOTO, BASIC, HELP |
| `src/console_text.asm` | PRINT, TXCRLF, PRINT_HEX8/16, PRINT_BIN8, HEXDIGIT |
| `src/hex_input.asm` | Неизменённые GETCHR, GET2 и BCTOA для HEX-загрузчика |
| `src/address_input.asm` | READ_HEX16 / алиас GETHL: единый редактор адреса |
| `src/ihex.asm` | Intel HEX DATA/EOF/SKIP и общая проверка checksum |
| `src/cf_boot.asm` | Загрузка CP/M и низкоуровневый CF-доступ |
| `src/messages.asm` | Сообщения основного монитора |
| `src/terminal.asm` | Общая ANSI-последовательность очистки экрана |
| `src/memview.asm` | Просмотр памяти; внутренние метки с префиксом `mv_` |
| `src/memedit.asm` | Редактор памяти с перемещаемым курсором; метки `me_` |
| `src/porttest.asm` | Работа с портами; внутренние метки с префиксом `pt_` |

Все INCLUDE подключаются один раз главным файлом. Модули не собираются
самостоятельно. Префиксы, а не отдельные пространства MODULE, сохраняют
простой доступ к существующим глобальным точкам входа.

## Что изменено

- Очистка экрана вынесена из memview: porttest больше не зависит от его строк.
- Удалены закомментированные копии HEX/string-процедур и устаревшее описание
  memview как отдельной программы по `$8000`.
- Переходы страниц используют `INC H` / `DEC H`: младший байт адреса всегда 0.
  Переходы `$FF00 → $0000` и `$0000 → $FF00` сохранены.
- Изменение порта/значения использует общие блоки `INC (HL)` / `DEC (HL)`.
  Переполнение 8-битных значений сохранено; при рисовании I/O не выполняется.
- Ввод адресов унифицирован; прежние GETHL/GETX, ECHO и парсер memview удалены.
  Подробности нового протокола и расчёт экономии — в ADDRESS_INPUT.md.
- PRINT_HEX16 не сохраняет HL повторно: его сохраняет весь вызываемый путь.
  Последний вызов заменён переходом, возвращающимся непосредственно вызывающему.
- CR/LF в строке дампа использует TXCRLF; финальный PRINT в обоих экранах —
  переход без лишнего RET. Формат экранов не менялся.
- DATA и SKIP используют один блок проверки checksum. Специальный EOF оставлен.
- Исправлен преждевременный NUL в build_info: теперь видна строка
  `Type ? for options` после даты. Это намеренное изменение видимого поведения.
- Добавлены комментарии о регистрах, стеке, побочных эффектах и ограничениях.
- Сборка отделена от записи в последовательный порт; отправка стала явной.

SIO, INIT, фильтрация консоли, разбор байтов Intel HEX и CF сохранены по потоку
инструкций; тест сравнивает их с исходной версией без комментариев/пробелов.
Дублирование аппаратных веток A/B оставлено намеренно: общая подпрограмма
изменила бы регистры, глубину стека и время выполнения драйвера.

A short delay was added before SIO initialization to the INIT.
The board uses an RC-generated reset signal, and the CPU can become
ready slightly earlier than the SIO. Without the delay, the SIO may
occasionally fail to initialize correctly after power-on.

## RAM, стек и интерфейсы

| Назначение | Адрес |
| --- | --- |
| Кольцевые буферы и служебные данные | `$4000..$408D` |
| Зарезервированный стек, растёт вниз | `$408E..$40AD` |
| STACK / baseaddr (слово) | `$40AE` |
| portno / value (байты) | `$40B0` / `$40B1` |
| me_cursor (слово) | `$40B2` |
| Первый свободный байт после переменных | `$40B4` |
| Внешний RAM-загрузчик | `$4100` |
| Временный образ нового монитора | с `$5000`, только фактическая длина |
| BASIC в конечном образе | с `$2000`; входы `$2000/$2003` |

Рабочая RAM задаётся EQU, в бинарник не выводится. Новых RAM-буферов нет.
32-байтный стек не увеличивался: это сохранило все адреса переменных.
По ручному подсчёту самый глубокий путь HEX-адреса в memview использует до
26 байт вместе с одним IRQ (PC + AF + HL в обработчике). Это не проверка
всех возможных аппаратных ситуаций; NMI, сторонние IRQ и пользовательский код
требуют отдельной оценки. Не добавляйте глубокие CALL в драйвер без пересчёта.

MAIN кладёт свой адрес в стек и делает JP к команде; выход из viewer/porttest —
обычный RET. Входы MEMDUMP/PORTTEST сохранены. MEMEDIT запускается командой E;
стрелки перемещают курсор, Enter начинает ввод байта и подтверждает сохранение,
Esc/Ctrl-C отменяют ввод. Используйте редактор только для заведомо безопасной
записываемой RAM. Стабильный внешний интерфейс —
RST $08 (вывод A), RST $10 (ввод A), RST $18 (состояние ввода).
Абсолютные адреса внутренних процедур не считаются стабильным API.

## Подготовка RAM-теста

```bash
bash test_new_monitor.sh
```

Требуются sjasmplus и srec_cat. Создаётся `build/monitor-test.hex` со смещением
`$5000`; последовательный порт не открывается. Смещение HEX — адрес доставки,
а не relocation машинного кода: монитор по-прежнему собран для `$0000`.

Для отправки добавьте **ваш существующий** `rom_loader.asm` в корень проекта:

```bash
bash test_new_monitor.sh --upload --port /dev/ttyUSB0
```

Требуется ascii-xfr. Скрипт собирает загрузчик, проверяет его размер,
отправляет оба HEX-файла и строку `g4100` с CR. Он не проверяет ответы платы
и не настраивает tty — используйте прежние настройки терминала.

Важное условие: до запуска должна быть подготовлена копия исходного ROM с BASIC
по вашей рабочей процедуре. Короткая загрузка не инициализирует хвост staging RAM.
Если ваш загрузчик переносит все `$4000` байт из `$5000..$8FFF`, соответствующий
хвост этой области должен содержать сохранённый исходный ROM, включая BASIC
в `$7000..$8FFF`. Если он копирует только монитор, исходный BASIC должен уже
находиться в конечной RAM. Скрипт сам это не обеспечивает и загрузчик не меняет.

Проверка размера загрузчика не доказывает его ORG или алгоритм копирования;
они должны оставаться частью вашей проверенной аппаратной процедуры.

## Проверка на плате

1. Соберите все три версии через тесты выше, убедитесь в отсутствии ошибок сборки.
2. Выполните вашу процедуру подготовки ROM-shadow, затем RAM-загрузку.
3. Проверьте приветствие, `?`, возврат в монитор и выбор обеих консолей.
4. В memview: `M0000`, `MFF00`, N/SPACE/P, стрелки, PgUp/PgDn, G с 1..4
   цифрами и Enter, затем Q. Проверьте округление `M1234` к `$1200`, Backspace,
   пустой Enter и отмену Ctrl-C/Esc во всех трёх местах ввода адреса.
5. В port monitor: A/D/S/W, переходы 00↔FF, Q. R/O испытывайте только на
   известном безопасном порту. Порты SIO, CF и отключения ROM не безопасные
   цели для произвольных записей. В IN/OUT старший байт адреса B равен нулю.
6. На заранее выделенной тестовой RAM проверьте корректную DATA-запись,
   ошибочную checksum, EOF и игнорирование type 04 без порчи reset-вектора.
7. Сравните сохранённый BASIC с исходной копией и проверьте нужные BC/BW и CP/M.
   Сценарий восстановления — ваш аппаратный reset с возвратом исходного ROM.

## Сохранённые ограничения

- Одиночный ESC в viewer ждёт следующий байт; таймаута нет.
- Enter в редакторе — CR; LF игнорируется. После Esc/Ctrl-C оставшиеся байты
  не удаляются из очереди: например, хвост ANSI-последовательности после Esc
  остаётся доступен следующему обработчику. Таймаут/очистка очереди не добавлены.
- HEX-загрузчик пишет DATA до проверки checksum; отката при ошибке нет.
- Адресные расширения type 02/04 игнорируются даже при ненулевом старшем адресе;
  это не полноценная поддержка HEX для памяти больше 64 КиБ.
- Некорректная EOF-запись с ненулевой длиной не исправлялась в этом рефакторинге.
- Viewer читает память отдельно для HEX и ASCII: изменяемые IRQ данные могут
  различаться между колонками. Снимок страницы в RAM не добавлялся.
- Чтение порта может иметь побочный эффект; запись может отключить консоль,
  изменить CF или банковую схему. Прерывания остаются включены, как раньше.

переводы строк нормализованы, логика не менялась. Его README и скрипт —
исторический материал, **не текущая инструкция**. Не запускайте старый скрипт
для проверки рефакторинга: он сразу отправляет данные на плату.
