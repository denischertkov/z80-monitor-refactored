# Единый ввод адреса и экономия

В `src/address_input.asm` добавлена общая `READ_HEX16`. Её вызывают команда G,
команда M и G внутри memview. Старое имя GETHL оставлено как алиас той же точки
входа без дополнительных байтов, но старый контракт флагов больше не действует.
GETX и ECHO удалены: внутри проекта других потребителей не было.

## Поведение

- 1..4 HEX-цифры в любом регистре; эхо букв — в верхнем регистре.
- Enter (CR) обязателен, в том числе после четырёх цифр.
- Пятая цифра и недопустимые символы игнорируются без эха.
- Backspace ($08) или DEL ($7F) удаляет последнюю цифру. В пустой строке
  приглашение не стирается. Работает и после достижения лимита четырёх цифр.
- Ctrl-C или Esc немедленно отменяет ввод.
- LF игнорируется. Буфер входа не очищается ни при подтверждении, ни при отмене.

При подтверждении печатается CR/LF. Отмена не печатает CR/LF: вызывающий
обработчик возвращается к приглашению монитора или перерисовывает viewer.

| Результат | Флаги | HL |
| --- | --- | --- |
| Адрес введён, включая 0000 | C=0, Z=0 | Адрес |
| Пустой Enter | C=0, Z=1 | 0 |
| Отмена | C=1, Z не определён контрактом | Не использовать |

Сначала проверяется Carry, только затем Zero. Признак пустоты вычисляется
по числу цифр B, а не по численному значению адреса.

| Вызывающий код | Успех | Пустой Enter | Отмена |
| --- | --- | --- | --- |
| G | JP (HL) | Возврат в монитор | Возврат в монитор |
| M | Открыть страницу HL & FF00 | Открыть 0000 | Возврат в монитор |
| G в memview | Открыть страницу HL & FF00 | Сохранить страницу | Сохранить страницу |

AF/BC/HL изменены; DE/IX/IY сохраняются. Рабочая RAM не добавляется.
Округление адреса осталось в memview. GET2 и преобразование байтов Intel HEX
не затрагивались. Общий редактор использует существующий HEXDIGIT для эха.

## Расчёт байтов

Сравнение сделано именно с **предыдущим архивом рефакторинга**, до унификации,
а не с первоначальными исходниками Гранта или исходным пользовательским монитором.

| Изменённый участок | До, байт | После, байт |
| --- | ---: | ---: |
| Старые GETHL / GETX | 46 | 0 |
| ECHO | 7 | 0 |
| READ_HEX16 с алиасом GETHL | 0 | 94 |
| Обработчик GOTO | 6 | 6 |
| Вход MEMDUMP, включая сохранение baseaddr | 12 | 9 |
| Запрос адреса внутри memview | 56 | 16 |
| **Всего** | **127** | **125** |

**Экономия — 2 байта ROM. Дополнительная RAM — 0 байт.**
Это расчёт по длинам кодировок инструкций Z80, не измерение собранного бинарника:
sjasmplus здесь отсутствует. Остальные инструкции/строки относительно предыдущего
рефакторинга не менялись; выравнивание и заполнители не добавлялись. Изменения
адресов меток и INCLUDE сами по себе байтов не добавляют.

Экономия небольшая: почти весь выигрыш от удаления дублирования потрачен на
Backspace, ограничение длины, отмену и различение пустого ввода/нулевого адреса.
Основной результат — единое поведение без увеличения объёма кода.

Расчёт воспроизводится без ассемблера:

```bash
python3 tests/size_delta.py
python3 tests/size_delta.py --instructions
```

Второй вариант перечисляет каждую учтённую инструкцию и её длину. Таблица
кодировок основана на [Zilog Z80 CPU User Manual](https://www.zilog.com/docs/z80/um0080.pdf).
Счётчик намеренно поддерживает только нужное подмножество инструкций и
останавливается при неизвестной форме; полноценный ассемблер он не заменяет.

Окончательная проверка с вашим sjasmplus 1.24.0:

```bash
python3 -m unittest discover -s tests -v
```

Тест сборки собирает исходный монитор, снимок до унификации и текущую версию,
измеряет длины бинарников и проверяет равенство фактической экономии расчётной.
Отдельные тесты проверяют все 256 входных байтов, 0/0000, пустоту, отмену при
каждой длине ввода, Backspace/DEL, превышение длины и три вызывающих обработчика.
Локальные JR редактора проверены на допустимые смещения по длинам инструкций.
Исполнение машинного кода, реальные SIO и IRQ по-прежнему требуют проверки на плате.
